# NIST SP 800-61 mapping

This lab follows the four phases in NIST SP 800-61 Revision 2. Revision 3 aligns incident response with the Cybersecurity Framework functions. The same controls sit in those functions: the detector and trail are Detect, the playbooks are Respond, and the forensics snapshots and VPC are Recover and Identify.

## Preparation

- Terraform creates the detector, rules, state machine, roles, quarantine pattern, deny-all policy, evidence bucket, and forensics VPC before an event.
- `containment_mode = notify_only` is a rehearsal switch.
- Runbooks record how to verify and roll back each playbook.
- Least-privilege roles limit what each function can change.

## Detection and analysis

- GuardDuty analyzes CloudTrail, VPC flow logs, DNS logs, and optional S3 data events.
- EventBridge keeps findings at or above `min_severity` and splits them by type prefix.
- The finding parser extracts the instance, access key, user, and bucket.
- A finding for another region or, when configured, another account is not contained. The result explains why.
- Evidence JSON stores the raw finding and the actions taken.

## Containment, eradication, and recovery

- EC2: replace the security groups with a quarantine group, tag the instance, and snapshot volumes.
- IAM: deactivate the access key and attach an explicit deny. Root and assumed-role sessions are reported for manual follow-up.
- S3: enable all four Block Public Access settings and refuse to modify the lab's own buckets.
- Step Functions retries Lambda service errors and notifies a human when a playbook throws.
- Runbooks describe how to restore the original security group, detach the deny policy, reactivate a key, and relax public access after a false positive.
- The forensics VPC is where an analyst can attach a volume created from a snapshot. It has no internet gateway.

## Post-incident activity

- Step Functions execution history and CloudWatch Logs show the decision path.
- The evidence bucket keeps the JSON record until the lifecycle rule expires it.
- CloudTrail records the containment API calls.
- Tags `IR-FindingId` and `IR-Status` mark what was changed.
- The dead-letter queue and its alarm show events that never started a workflow.
